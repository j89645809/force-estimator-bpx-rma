# Fz 误差定位：力大小、方向、机身姿态（2026-10-16）

结论：当前首要现象是 Fz 双向幅值低估，且在接近水平的机身姿态下已经明显存在。不能据现有数据认定“大倾角导致失败”，也不能直接把拟合增益当作校准部署。此次只做诊断，未训练、未改权重、未修改部署模型。

## 数据与口径

- 使用 closedloop25_v3 的 10 条运行文件：每模型 5 场景 × 46 环境 × 1200 步；剔除前 50 步后，每模型 264500 帧。原始文件哈希与全部分层结果保存在 diagnosis.json。
- Fz 指机身坐标系 Z 分量；误差=预测−实际标签，单位 N。标签是实际 body_external_wrench 旋转到机身坐标系后的值，乘回 80。这里的方向也按机身坐标系定义，并非世界坐标上下。
- 方向：真实合力≥2 N 后，Fz/合力>0.5 为向上锥区，<−0.5 为向下锥区，其余为近水平带；<2 N 单列。水平带并不表示 Fz=0。
- 力区间按真实合力划分，15/30/45 N 边界容差分别为 0.0001/0.0001/0.001 N。
- 姿态由保存的 25 帧历史中 projected_gravity[9:12] 恢复，倾斜角=acos(−gz/|g|)。play 配置关闭观测噪声；重力范数约 1。高度来自索引 12。历史 index 0 为最新帧，每 100 步保存一次，可恢复每段连续 25 步。按 step=100i−j 对齐对应预测和标签，去掉启动与被清零历史；未插值。
- 每模型约 6.32 万姿态配对帧，属于间隔采样窗口，不能代表所有短瞬态。无 yaw 信息；roll/pitch 可由重力恢复，但大倾角覆盖不足。
- 230 个场景×环境轨迹不是 230 个独立随机种子：每场景仅 1 种子，时间帧相关。本报告为描述性诊断，不做帧级显著性检验或因果宣称。
- 聚合使用 float64，旧验收报告 float32 逐轴累加导致 Fz RMSE 约 0.001 N 的显示差异；不影响结论。

## 5. 下一步补数据决策与停止盲目加权

1. 先审计训练链路：核实原训练数据的 Fz 分布、单位/80 归一化、坐标变换、历史输入、接触力与关节力矩通道。当前约0.53的响应斜率值得检查，但不能只凭它认定存在缩放 bug。最新微调使用旧 dual 轨迹的事实已知；原始标签覆盖统计现已完成，详见下表；此审计仅针对最新 input_fair_v2 微调集，不代表 v8a 及更早预训练数据。
2. 优先做小批量诊断采集：在近水平姿态下，配对 ±Z 及斜向力，明确覆盖 5/10/15/20/30/40/45 N。每个幅值匹配相同方向集合、不同独立种子，补齐正负垂直分量，避免幅值和方向一一绑定。加入零力和近水平力锚点。先看真实 Fz→预测 Fz 曲线是否仍双向衰减。
3. 第二层采集才是姿态：在可稳定实现的平地/坡面和初始姿态条件下，覆盖 0–5/5–10/10–20° 的实际 roll/pitch，正负俯仰与横滚分别标记。按实际达到的姿态分箱，不能以初始设定姿态代替。与第一层尽量匹配力大小和方向，明确坡面、接触状态等仍可能混杂。
4. 每步记录真实四元数、位置/高度、速度、角速度、接触状态/载荷、力矩、机身/世界系实际外力、施加命令和reset原因。采集完整历史和时间戳，避免本轮姿态稀疏窗口遗漏瞬态。
5. 数据用途先分开：本轮已查看轨迹作为诊断集，不再作为盲测；新采集按完整轨迹/种子划分训练、验证、独立验收，不能随机拆相邻帧。保留 Ramp/Sweep/Release/Reverse/Full3D 锚点及切换窗口。
6. 训练启动条件：先排除量纲/输入错误，确认相应垂直力单元确实覆盖不足或在正确数据上仍欠拟合，再做最小规模补数据对照。保持原损失基线，先比较“补数据”与“不补数据”；只有验证结果支持时再比较权重方案。不直接用此次盲测拟合倍率、调权或选择部署版本。

现阶段不制定固定新增样本百分比。以力大小×方向×姿态单元的覆盖和独立轨迹数量决定采集量；稳定大力垂直分量优先于继续堆普通反向稳态样本。
